# LinkedHashSet

## 용도
- **삽입 순서를 유지**하면서 중복을 허용하지 않는 집합
- 방문 이력·처리 이력처럼 **순서 있는 중복 제거** 필요 시
- 출력 결과가 삽입 순서를 따라야 하는 집합
- 내부: **LinkedHashMap**으로 구현 (버킷 + 이중 연결 리스트)

## 장점
| 항목 | 내용 |
|------|------|
| **삽입 순서 유지** | `for-each` 순회 시 삽입한 순서대로 반환 |
| **O(1) 연산** | HashSet과 동일하게 add/contains/remove 평균 O(1) |
| **예측 가능한 순회** | HashSet의 무작위 순회 문제 없음 |

## 단점
| 항목 | 내용 |
|------|------|
| **메모리 오버헤드** | 각 엔트리에 `before + after` 포인터 추가 → HashSet 대비 약 2포인터/엔트리 |
| **삽입·삭제 추가 비용** | 연결 리스트 포인터 갱신 필요 (HashSet 대비 미미하게 느림) |
| **접근 순서 재정렬 불가** | `get(e)` 후 순서가 바뀌지 않음 (LRU 불가 → LinkedHashMap 사용) |

## 성능

| 연산 | LinkedHashSet | HashSet | 비고 |
|------|--------------|---------|------|
| `add(e)` | O(1) ≈ | **O(1)** | 포인터 갱신 비용으로 미미하게 느림 |
| `contains(e)` | O(1) ≈ | **O(1)** | 해시 접근으로 거의 동일 |
| `remove(e)` | O(1) ≈ | **O(1)** | 연결 리스트 포인터 갱신 추가 |
| 삽입 순서 순회 | **O(n)** | X | LinkedHashSet은 순서 보장 |
| 메모리 사용 | 더 많음 | **적음** | `before/after` 포인터 추가 |

> **결론**: 순서 없어도 됨 → HashSet / 삽입 순서 유지 필요 → LinkedHashSet / 접근 기반 LRU → LinkedHashMap

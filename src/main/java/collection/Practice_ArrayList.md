# ArrayList

## 용도
- **인덱스 기반 랜덤 접근**이 빈번한 데이터 저장
- **삽입 순서를 유지**해야 하는 목록 관리
- 데이터를 끝에 계속 추가하고 인덱스로 조회하는 패턴 (로그, 이벤트 목록 등)
- 내부적으로 **Object[] 배열**을 사용하는 동적 배열 구현체

## 장점
| 항목 | 내용 |
|------|------|
| **랜덤 접근 O(1)** | `get(index)` = 배열 포인터 연산 1회, 위치 계산 즉시 완료 |
| **캐시 친화적** | 연속 메모리(배열)로 CPU 캐시 라인 히트율 높음 → 순차 순회 빠름 |
| **끝 추가 amortized O(1)** | `add(e)` 대부분 O(1), 배열 확장 시만 O(n) |

## 단점
| 항목 | 내용 |
|------|------|
| **중간 삽입·삭제 O(n)** | `add(i, e)` / `remove(i)` → 이후 요소 전체 쉬프트 |
| **배열 재할당 비용** | 용량 초과 시 1.5배 크기 새 배열에 전체 복사 (초기 용량 지정으로 완화) |
| **메모리 낭비** | 용량의 여유분(최대 1.5배)을 미리 확보 |

## 성능

| 연산 | ArrayList | LinkedList | 비고 |
|------|-----------|------------|------|
| `get(i)` | **O(1)** | O(n) | 인덱스 = 배열 주소 계산 vs 노드 순회 |
| `add(0, e)` | O(n) | **O(1)** | 전체 쉬프트 vs 헤드 포인터 교체 |
| `add(e)` (끝) | **amortized O(1)** | O(1) | 배열 끝 추가 vs 테일 노드 연결 |
| `remove(i)` | O(n) | O(n) | 쉬프트 vs 탐색 |

> **결론**: 조회 위주·순차 탐색 → ArrayList / 빈번한 앞 삽입·삭제 → LinkedList

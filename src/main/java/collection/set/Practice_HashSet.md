# HashSet

## 용도
- **중복 없는 원소 집합** 관리
- 원소의 **존재 여부를 빠르게 확인**해야 할 때
- 리스트의 **중복 제거** 필요 시
- 순서가 중요하지 않은 집합 연산(교집합·차집합·합집합)
- 내부적으로 **HashMap**을 사용 (키만 사용, 값은 더미 객체)

## 장점
| 항목 | 내용 |
|------|------|
| **add/contains/remove 평균 O(1)** | 해시 함수로 버킷 위치 직접 계산 → 탐색 없음 |
| **중복 자동 제거** | `add("a")` 이미 존재하면 false 반환, 집합 상태 유지 |
| **높은 처리량** | 대용량 데이터에서 TreeSet 대비 압도적으로 빠름 |

## 단점
| 항목 | 내용 |
|------|------|
| **순서 미보장** | 삽입 순서·정렬 순서 모두 보장 안 함 (버킷 위치에 따라 결정) |
| **해시 충돌 시 성능 저하** | 동일 hashCode 원소가 많으면 버킷 내 LinkedList/TreeNode 탐색 |
| **null 하나만 허용** | null은 버킷 0에 저장, 두 번째 null 추가 시 무시 |

## 성능

| 연산 | HashSet | TreeSet | 비고 |
|------|---------|---------|------|
| `add(e)` | **O(1) 평균** | O(log n) | 해시 버킷 접근 vs Red-Black Tree 삽입 |
| `contains(e)` | **O(1) 평균** | O(log n) | 해시 버킷 접근 vs 트리 탐색 |
| `remove(e)` | **O(1) 평균** | O(log n) | 해시 버킷 접근 vs 트리 삭제 |
| 정렬 순회 | X (지원 안 함) | **O(n)** | HashSet은 정렬 보장 없음 |
| `first()/last()` | X | **O(log n)** | HashSet에 없는 기능 |

> **결론**: 단순 중복 제거·빠른 조회 → HashSet / 정렬·범위 연산 필요 → TreeSet

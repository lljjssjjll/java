# LinkedList

## 용도
- **양 끝(앞·뒤) 삽입·삭제**가 빈번한 경우
- **Deque(덱)** 구현 — 스택과 큐를 모두 대체 가능
- 크기가 자주 변하고 인덱스 접근이 거의 없는 경우
- 내부적으로 **이중 연결 리스트(doubly linked list)** 구조

## 장점
| 항목 | 내용 |
|------|------|
| **양 끝 삽입·삭제 O(1)** | `addFirst/addLast/removeFirst/removeLast` = 헤드·테일 포인터만 교체 |
| **크기 동적 관리** | 배열 재할당 없음, 노드 추가·제거만으로 크기 변경 |
| **Deque 인터페이스** | 스택(`push/pop`)·큐(`offer/poll`)·덱 API 모두 지원 |

## 단점
| 항목 | 내용 |
|------|------|
| **인덱스 접근 O(n)** | `get(i)` = 헤드(또는 테일)에서 노드를 하나씩 탐색 |
| **캐시 비친화적** | 노드들이 힙 전역에 흩어져 있어 캐시 미스 빈번 |
| **메모리 오버헤드** | 노드당 데이터 외 `prev + next` 포인터 2개 추가 |

## 성능

| 연산 | LinkedList | ArrayList | 비고 |
|------|-----------|------------|------|
| `addFirst(e)` | **O(1)** | O(n) | 헤드 포인터 교체 vs 전체 쉬프트 |
| `removeFirst()` | **O(1)** | O(n) | 헤드 포인터 교체 vs 전체 쉬프트 |
| `get(i)` | O(n) | **O(1)** | 순차 탐색 vs 배열 인덱스 접근 |
| `add(e)` (끝) | O(1) | amortized O(1) | 테일 노드 연결 vs 배열 끝 추가 |

> **결론**: 인덱스 접근 거의 없고 앞·뒤 삽입·삭제 중심 → LinkedList / 그 외 → ArrayList  
> 단순 큐·스택 용도라면 **ArrayDeque**가 캐시 효율 면에서 LinkedList보다 빠름
